# BENCHMARK — pattern analysis, 2026-10-18

**Method note:** this is reasoning from the known public character of each site (structure, tone, visual register, entry paths) — not screenshots or audits. Mechanisms, not aesthetics.

## linear.app
**Borrow**
1. **Load-bearing restraint** — few elements per screen, each doing work; whitespace as hierarchy.
2. **Motion as state demo** — small purposeful transforms that *show* transitions rather than decorate.
3. **Copy discipline** — name the thing, explain it in one declarative sentence, move on.
**Avoid:** under-explanation. Linear sells to a category-fluent audience; Quantiviq's offer is novel and needs more exposition per screen.

## palantir.com/platforms/aip
**Borrow**
1. **Workflow-over-features framing** — show the system operating inside an organization's real loop, not a feature grid.
2. **Authority through specificity** — naming real constraints reads as competence.
3. **Serious dark register** — infrastructure, not startup-demo.
**Avoid:** gatekeeping opacity — no visible pricing or simple entry; entry must stay obvious and low-friction on Quantiviq.

## mckinsey.com/.../quantumblack/how-we-help-clients
**Borrow**
1. **Audience-segmented entry** — paths in by role/industry/question.
2. **Method as content** — "how we help" structures the offer around the client's situation.
3. **Editorial long-form typography** — dense text treated with respect; signals senior audience.
**Avoid:** corporate sameness and jargon soup; hero imagery that carries no information.

## bcg.com/x
**Borrow**
1. **Build-vs-advise clarity** — "we build" stated plainly; positioning in one verb.
2. **Case-driven narrative arcs** — work told as stories with tension and resolution.
3. **Bold typographic scale contrast** — huge statements against small precise captions.
**Avoid:** buzzword density ("AI at scale" ×N) with no mechanism behind the words.

## vercel.com
**Borrow**
1. **Terminal/code as first-class visual material** — mono type and real snippets as design elements.
2. **Ship cadence as credibility** — visible changelog/product-notes rhythm proves the org builds.
3. **One accent, used sparingly** — dark theme with a single high-contrast accent applied consistently.
**Avoid:** developer-only assumptions — Vercel writes for engineers; Quantiviq's CEO/COO readers need plain-language bridges next to technical proof.

## ideo.com
**Borrow**
1. **Narrative portfolio** — work presented as stories with the process visible, not just outcomes.
2. **Human warmth** balancing technical content.
3. **Opinionated POV** — essays that take a stance attract the right clients and repel the wrong ones.
**Avoid:** style-over-specificity — airy abstraction where mechanism and result dissolve.

## What this means for Quantiviq
- Few elements, each load-bearing; mint `#7cd9b7` is the single luminous signal (Linear + Vercel restraint).
- Show the system operating — the org simulator and OS diagram are the centerpiece, framed as workflow not features (AIP).
- Segment entry by the visitor's question (McKinsey): beats and CTAs prefill intent.
- Editorial long-form for `/notes` builds authority; treat text as design (QuantumBlack + IDEO).
- Say what we build and what we do NOT promise in the same breath; negative results stay visible.
- Never: hidden entry paths, buzzwords without mechanisms, robot clichés, developer-only copy.
